# ReDotUpdater

`ReDotUpdater.exe` is a separate, standalone (~0.5 MB, static CRT, system DLLs only) one-click updater for **portable** ReDot folders. It is not part of `ReDot.exe`, not an installer, needs no administrator rights for ordinary folders, and has no Qt dependency. Sources are in `updater/` (own `CMakeLists.txt`).

## What it does when launched

1. Finds ReDot: a running ReDot's folder, the updater's own folder, then `ReDot*` folders under Desktop, Downloads, Documents, the user profile, Program Files, `C:\` and `D:\` (two levels deep). One match is used automatically; several or none show a chooser/Browse dialog.
2. Identifies the version: `redot-version.json` if present. Without it, only the public v1.0.0 layout (a `ReDot.exe` reporting 0.3.0 **and** `THIRD-PARTY-NOTICES.txt`) is accepted and treated as **1.0.0**. Anything else (e.g. development builds) is refused and never modified.
3. Lists `https://api.github.com/repos/Eyal2012/redot/releases`, ignores drafts, prereleases and pre-release tags, picks the highest stable semantic version and requires the official `ReDot-v<ver>-Windows-x64.zip` and `.zip.sig` assets under `https://github.com/Eyal2012/redot/releases/download/`.
4. If newer: waits (without ever closing it) while ReDot is running, then downloads, **verifies the ECDSA P-256 signature over the ZIP's SHA-256 against the key built into the updater** (a checksum from the same download source is never trusted), validates the ZIP, extracts into `<ReDot folder>\.redot-update\staging-*`, checks the signed `redot-version.json` matches the release, then swaps files in with a write-ahead journal. Every replaced file is first renamed into `.redot-update\backup-<oldversion>-*`.
5. On any failure (or at next start after an interruption) the journal is rolled back: backed-up files return, files that did not exist before are removed. Files that are not in the package (recordings, notes, extra plugins) are never touched, and user-data names (`settings-v1.txt`, `scenes-v1.json`, `workspace-layout-v1.txt`, `PandaClip\`) are rejected inside a package. Settings, scenes, hotkeys and logs live in `%LOCALAPPDATA%\PandaClip\` and are never accessed.
6. Shows "Update Complete" with the release notes and starts the new ReDot. The newest backup is kept in `.redot-update`.

The updater writes only inside the chosen ReDot folder (`.redot-update` and the replaced files). Command line (for testing): `--install-dir <folder>`, `--check-only`, `--no-launch`, `--log <file>`.

## Requirements for every release ZIP

* Name `ReDot-v<major.minor.patch>-Windows-x64.zip`, tag `v<major.minor.patch>`, with a **second asset** `<same name>.sig` (64-byte raw signature). Both uploaded to the release; release must not be a draft or prerelease.
* One top-level folder `ReDot-v<ver>\` (or files at the root) containing `ReDot.exe`, `redot-version.json` (generated by the ReDot CMake build; `version` must equal the tag and `ReDot.exe`'s file version), the Qt and FFmpeg DLLs, plugins, QML and licences — i.e. a complete portable folder. No ZIP64, encryption, symlinks, traversal or reserved names; at most 3 GiB unpacked.
* Build it with `tools\New-PortableRelease.ps1 -ReleaseDirectory <build\...\Release>`, which checks the version agreement, zips, and signs.
* `updaterProtocol` in the manifest is 1. Raise it only if a future package needs a newer updater (older updaters then stop with an instruction to download the latest updater).
* The updater never deletes files that a newer package stopped shipping; stale files remain harmlessly.

## Signing key

`ReDotSignTool genkey` created the key pair. The **public** key is compiled into `updater/public_key.h`. The **private** key is `%USERPROFILE%\.redot-signing\redot-release-private.blob` — back it up privately and never upload or commit it. If it is lost or leaked, a new updater with a new public key must be distributed manually; old updaters cannot be re-keyed.

## Tests

`ReDotUpdaterTests <workdir> [--legacy-exe <v1.0.0 ReDot.exe>] [--real-zip <v1.0.0 zip>]` runs version, feed, detection, hostile-ZIP, mock update, rollback, crash-recovery, signature, network-failure and running-process checks entirely under the work directory, with a fake network and throwaway keys.
